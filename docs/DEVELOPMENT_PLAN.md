# 开发计划

仅记录可定位的问题。每项独立修改、验证后勾选；DOCX 与代码冲突先核实玩法意图，不直接改行为。

## 传古符文镶嵌（分阶段）

材料：桌面 `新建文本文档.txt` 列出 20 个符文和 30 个阴性／中性／阳性组合；`data/fuwen/` 有 54 份可解析的效果 JSON，带 `4`、`5` 后缀的文件分别对应 4 孔、5 孔效果，六个五枚符文组合使用无数字后缀文件。`data/items/31541.json` 至 `31560.json` 对应这 20 个不可装备的符文。物品定义的 `物品类别` 可含多个标签，传古遗物有多极性实例，且一些遗物本身也带 `传古符文` 标签；识别可镶嵌材料时须使用这 20 个符文的精确物品 ID，不能只按类别判断。

1. [x] **规则与资料定稿**：`gamedata/overrides/ancient-rune-combinations.mjs` 显式对应 20 枚符文、30 个组合与全部 54 份效果文件，含异名文件映射；“魔山”5 孔在 4 孔组合上再加一枚“巨物”，无后缀文件对应六个五枚符文组合。组合只看符文种类和数量、不看顺序；可拆卸但不返还符文；多极性遗物可触发任一对应极性的组合。效果兼容性逐条记录在 `docs/ANCIENT_RUNE_EFFECT_AUDIT.json`，由 `scripts/audit-ancient-rune-effects.mjs` 生成。
   - [x] 对照 `docs/WOD教科书计划.docx` 和现有技能效果，把 `data/fuwen/` 中“脆弱性”“技能等级奖励”“技能效果奖励”的类型别名规范为现有格式；`scripts/normalize-ancient-rune-effects.mjs` 可在本地数据重新导入后重复执行。持有者解析告警从 159 条降为 0；目标效果待核验从 186 条降为 152 条。`data/` 被 Git 忽略，规范化脚本和审计记录用于复现与复查本地 JSON 改动。
2. [x] **容量与组合判定**：从遗物 `物品类别` 精确读取阴／中／阳性，从 `详细属性.特性` 的“可以镶嵌n次”读取容量；按符文 ID 多重集合、孔数和极性匹配组合。未匹配或极性不符时不追加效果，遗物原有效果仍保留。纯规则测试覆盖重复符文、顺序和多极性。
3. [x] **物品实例持久化与镶嵌操作**：`item_instances.socketed_rune_item_ids` 绑定具体遗物实例，跟随角色／团队仓库流转；仓库 API 在事务中校验角色归属、符文实例、孔位和重复提交，消耗当前角色仓库符文，拆卸不返还。显式迁移脚本 `migrations/25-ancient-rune-sockets.mjs` 先备份运行库，数据库契约与测试夹具已更新；运行时不自动迁移。
4. [x] **镶嵌页面**：角色仓库中的传古遗物有镶嵌入口；弹窗显示原有效果、孔位、当前已镶嵌符文、当前角色仓库可选符文及匹配组合追加的持有者／目标效果。镶嵌或拆卸后刷新仓库、装备和角色详情；满孔未匹配、极性不符或组合效果资料不可用时显示提示。组合判定和效果资料由服务端返回，页面不计算规则。
5. [x] **角色实例与战斗接入**：152 条目标效果格式已处理，审计中无待核验目标效果。已装备遗物上的组合持有者效果进入现有 `character-instance` 计算，目标效果随调用物品进入战斗计划；卸下遗物后效果失效。效果记录保留遗物实例 ID、组合名称和来源，进入属性来源、战报输入快照与回放校验。真实角色实例测试覆盖技能效果增伤和治疗、护甲、脆弱性减伤与负值回血。
   - [x] 37 条目标护甲奖励、42 条目标伤害奖励：现有战斗效果转换与引擎已按 `伤害方式`、`攻击方式` 和普通／重击／致命三档读取修正；固定护甲最低将穿甲伤害降至 0，伤害奖励在防御后追加，未改写符文 JSON。新增对应的战斗与伤害管线测试并通过。
   - [x] 61 条目标脆弱性与已有技能／物品的同类效果：按伤害方式、攻击方式及普通／重击／致命三档分别转换和匹配。常驻与限时修正保留固定百分点、独立百分比项、来源和持续时间；固定值相加，百分比倍率相乘，再与常规基准 `100%` 合成。护甲先结算，脆弱性随后作用于穿甲伤害；大于 `100%` 加深、`0%` 免疫、小于 `0%` 回血，后置伤害奖励再追加。战报与计算轨迹区分脆弱性／抵抗性／抗性超出预期。新增解析、角色实例、公式和战斗测试。
   - [x] 12 条目标“对技能效果的奖励”：沿用现有技能效果字段，战斗单位带入角色实例的常驻奖励，限时效果按技能名／技能类别实时匹配，伤害和治疗共用先乘百分比再加固定值的计算；不计入技能等级。新增转换、战斗和治疗测试并通过。
6. [x] **端到端验证与文档**：集成测试覆盖 4／5 孔、重复符文、三种极性、多极性遗物、同名遗物不同实例、库存不足、仓库流转、回滚、装备与卸下、目标效果和战报回放；API 自检覆盖同时提交只成功一次、镶嵌结果展示与拆卸不返还。`docs/PROJECT_OVERVIEW.md` 和 `docs/ARCHITECTURE.md` 已记录玩法与数据流。`npm run db:verify`、`npm test`（301 项）、`npm run test:api`、`npm run build` 均通过，已核对 `git diff`。

## 高优先级

- [x] `createDungeonExploration` 的多战报索引与地城记录同事务提交；写入抛错时回滚并清理本次展示文件（进程崩溃后的跨 SQLite/文件恢复仍需另行设计）。
- [x] 明确产品目标：本项目只用于 WOD 配装和战斗模拟，探索不发放经验、金币或物品；取消探索奖励结算任务，不把原版成长循环当作缺失功能。
- [x] 明确模拟探索不受地城等级、准备时间和重复探索次数限制；取消对应实现任务，移除地城页无关的等级与准备时间列。
- [x] 按物品源详情与本地玩法确认装备唯一性、三种使用次数和耐久边界：配装检查英雄/队伍唯一；模拟内扣剩余次数、跨房间累计地城次数、每房间重置战斗次数；不写回仓库，不处理装备耐久。

- [x] 已审查战报导入与本地战报的职责；按本地模拟器目标移除原版 HTML 导入页面、API、解析器及其专用测试，保留本地模拟战报和事件回放校验。
- [x] 明确地城只需固定训练木桩，不还原原版怪物配置；删除三个地城的演示怪物，统一为本地木桩，保留两个房间验证跨房间模拟规则。技能/物品效果的证据工作与怪物数值无关，另见下项。
- [x] 取消“按原版战报逐项补证据”任务；后续发现具体技能、物品效果或计算差异时，直接定位并修改相关公式、实现和测试，不再引入原版战报导入。
