# 开发计划

仅记录可定位的问题。每项独立修改、验证后勾选；DOCX 与代码冲突先核实玩法意图，不直接改行为。

## 高优先级

- [x] `createDungeonExploration` 的多战报索引与地城记录同事务提交；写入抛错时回滚并清理本次展示文件（进程崩溃后的跨 SQLite/文件恢复仍需另行设计）。
- [x] 明确产品目标：本项目只用于 WOD 配装和战斗模拟，探索不发放经验、金币或物品；取消探索奖励结算任务，不把原版成长循环当作缺失功能。
- [x] 明确模拟探索不受地城等级、准备时间和重复探索次数限制；取消对应实现任务，移除地城页无关的等级与准备时间列。
- [x] 按物品源详情与本地玩法确认装备唯一性、三种使用次数和耐久边界：配装检查英雄/队伍唯一；模拟内扣剩余次数、跨房间累计地城次数、每房间重置战斗次数；不写回仓库，不处理装备耐久。

## 中优先级

- [x] 审查 `server.mjs` 路由、`battle-service.mjs` 装配/写入与 SQLite 仓库：旧单层/整座地城入口中途写入失败可留下部分战报，已复用仓库事务并验证回滚。路由仍是协议适配，仓库集中持久化；目前没有值得新增模块的独立变化原因。
- [x] 统一角色实例到模拟器的数值入口：旧单英雄地城入口改用角色实例建战斗单位；新版探索快照删除重复的旧角色行派生计算。保留模拟器逐回合重算，以正确处理临时效果。
- [x] 已审查战报导入与本地战报的职责；按本地模拟器目标移除原版 HTML 导入页面、API、解析器及其专用测试，保留本地模拟战报和事件回放校验。
- [x] 明确地城只需固定训练木桩，不还原原版怪物配置；删除三个地城的演示怪物，统一为本地木桩，保留两个房间验证跨房间模拟规则。技能/物品效果的证据工作与怪物数值无关，另见下项。
- [x] 取消“按原版战报逐项补证据”任务；后续发现具体技能、物品效果或计算差异时，直接定位并修改相关公式、实现和测试，不再引入原版战报导入。

## 低优先级

- [x] 一次地城探索只装配一次技能目录，避免每场战斗重复读取技能元数据。
- [x] 核对运行、构建和测试引用后，删除无调用的旧套装抓取脚本、被跟踪的 Python 缓存及无引用的旧资源。单层战报、物品 ID 与效果结构的兼容分支仍有调用或历史数据依赖，保留。
- [x] 修正 `src/App.jsx` 装备候选失效：进入装备页及仓库流转、市场购买后刷新装备数据，切换角色时清除上一角色的仓库错误；不增加全局状态层。
- [x] 建立最小 AI 开发入口、玩法差异和真实架构文档。
- [x] 架构减肥：删除未使用的旧版战报页面，市场套装筛选直接调用仓库，移除目标优先级的同结果分支及未使用的战斗上下文字段；逐项验证后保留现有模块边界。
- [x] 确认模拟器不提供掉落：移除仅由测试引用的掉落唯一性账本、仓库读写方法、规则问答及实验策略；运行库和测试库旧表均为空，保留 `uniqueness_ledger` 空表与 SQLite 契约以兼容现有数据库，不影响配装的英雄唯一/队伍唯一校验。
- [ ] 行动设置页的调用物品本地预检与服务端校验有重叠；先核对两者错误提示和交互，再决定是否缩减本地判断，避免保存体验退化。
